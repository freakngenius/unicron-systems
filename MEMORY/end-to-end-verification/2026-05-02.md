```
./unicron-platform/src/components/live/LiveSystem.tsx:19:38
Type error: Property 'env' does not exist on type 'ImportMeta'.

  19 | const COST_SUMMARY_URL = import.meta.env.VITE_COST_SUMMARY_URL as string | undefined;

Error: Command "npm run build" exited with 1
```

**Root cause.** Stream C committed the Vite-based operator UI at repo-root `unicron-platform/`. The Pathfinder Next.js project's `tsc --noEmit` step type-checks all `.ts/.tsx` reachable from the project root that aren't excluded. `Pathfinder/.vercelignore` is intentionally empty (per its own header comment) so the parent repo-root `.vercelignore` (`Pathfinder/`, `Product/`) doesn't strip Pathfinder's tree — but neither file excludes `unicron-platform/`. Result: Next.js types `import.meta.env` (Vite-only) and fails. CI doesn't catch this because CI runs `npm run build` inside the `Pathfinder/` directory only; Vercel runs from repo root with the broader file scope.

This has been the failure mode since PR #34 (2026-05-01 17:32 UTC). **PR #43, #44, #45, #46 were each attempted fixes that addressed downstream symptoms (lockfile, env-reads, sourceOnboarder contract, maxDuration cap) but never the actual `import.meta.env` typecheck failure.** The maxDuration error was a real downstream problem that would surface only once typecheck passed; right now we never get past typecheck.
