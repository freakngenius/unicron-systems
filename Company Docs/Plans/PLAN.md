# Unicron Systems — 5-Pattern Prototype Suite — Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy a Next.js app at `unicron-systems.vercel.app` that demonstrates all 5 living-systems patterns (Mycelium, Beehive, Ant Colony, Murmuration, Slime Mold) as live prototypes wired to Supabase + Anthropic + Notion, each demoable in <60s, with a meta-dashboard at `/app`.

**Architecture:** Single Next.js 14 App Router app, extended from the existing repo root. Routes: `/` (existing paradigm-map landing, preserved), `/app` (meta-dashboard), `/app/{mycelium,beehive,colony,murmuration,slime}` (pattern UIs), `/api/*` (pattern + cron endpoints). Shared libs for Supabase / Anthropic / Notion / logger. Supabase for state; Notion for promoted artifacts; Anthropic Sonnet (orchestration) + Haiku (fan-out). Tailwind + shadcn/ui with dark-theme tokens matching the paradigm map.

**Tech Stack:** Next.js 14 App Router • TypeScript strict • Tailwind + shadcn/ui • Supabase (Postgres + Realtime) • `@anthropic-ai/sdk` • `@notionhq/client` • Zod • Vitest • Playwright • Vercel + Vercel Cron

## Repo-layout decision

**Extend the existing root Next.js app.** Reasons:
1. Repo root already deploys to `unicron-systems.vercel.app` via the Vercel project.
2. `/` is already the paradigm-map landing (rAF ping-pong video with signup) — maps cleanly to the spec's `/ → marketing landing` slot. Do NOT touch it except to link to `/app`.
3. One deploy, one lockfile, one CI surface.

Subfolder `Product/` is preserved for non-code artifacts (the spec and a second `.env.local` copy). Do **not** put the app there.

The existing Netlify paradigm-map deploy (different repo) stays untouched — it's referenced only as a link.

## Key design decisions (authoritative; deviations require note in PR)

| Decision | Choice | Why |
|---|---|---|
| Mycelium similarity | LLM-based ("is this signal semantically redundant with any of these?") via one Claude Haiku call per drop | Spec permits either; avoids pgvector setup; single round-trip |
| Beehive orchestration | Synchronous server-side `run()` called from `POST /api/beehive/run`, returns 202 with `run_id`, client polls `GET /runs/:id` every 500ms | Vercel after() semantics are flaky in dev; polling is simplest and sufficient for ≤20s runs |
| Colony fan-out | `Promise.allSettled` over a custom semaphore (concurrency=10); SSE via `ReadableStream` in a Route Handler | No external queue needed; stays within Vercel limits at 50 workers |
| Murmuration cycle | All 7 agents run cycle K in parallel; barrier before K+1 | Matches "local-peer" semantics; keeps each cycle <5s |
| Slime judging | One Haiku call per alive candidate per cycle, parallelized | 10 candidates × 3 cycles = ≤30 calls; fast enough |
| Auth | `ADMIN_PASSCODE` cookie check in `middleware.ts` on `/app/*` and mutating `/api/*` | Spec says "simple gate"; cookie + header works |
| Styling | Tailwind + shadcn/ui with CSS-variable tokens matching paradigm map | Spec prescribes dark theme + specific tokens |
| Seed loading | `npm run seed` wipes and repopulates via service-role key against Supabase | Idempotent; safe to re-run during demo |
| Supabase migrations | SQL files in `supabase/migrations/`, applied via `mcp__supabase__apply_migration` (or CLI) | Keeps schema in git |
| LLM models | `claude-sonnet-4-6` for orchestration/judgment; `claude-haiku-4-5-20251001` for fan-out/classification | Spec §1 |
| Notion schema | One DB per pattern under product page; IDs cached in `notion_meta` Supabase table | Spec §10 |

## Execution notes

- Commit after every meaningful unit with Conventional Commits.
- Push after each chunk (at minimum).
- If a Supabase migration fails, stop and ask — don't retry destructively.
- Seed scripts must be idempotent.
- Never bypass pre-commit hooks.
- LLM test-doubles: prefer a shared `lib/anthropic-mock.ts` for unit tests; integration/e2e can hit real API with a low-cost fixture path.
- Parallelism: after Chunk 1 green deploy, Chunks 2–6 are independent. If running with subagents, fan them out.
- Worktrees: use one per pattern if subagent-driven parallel execution is available. Otherwise sequential on `main` is fine.

## Blockers that require user input (none expected; listed for honesty)

- Missing or expired Anthropic / Supabase / Notion keys.
- Notion integration not connected to the product page (returns 404).
- Vercel project disconnected from the repo.
- Any explicit destructive request (e.g., drop tables).

Everything else: make a reasonable default and note it in the PR description.
