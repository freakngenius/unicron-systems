## Problem (verified live)

(192/192 score, 192/192 recommended_action) but the Lead Feed in Notion
is still mostly bare:

| Construction rows | Count |
|---|---|
| Total | 192 |
| Has a Notion page | 31 |
| **No Notion page at all** | **161** |
| Of the 31 with a page, written pre-Z17 as bare shell | ~31 |

`backfillNeedsWork()` returned false for any row already DB-enriched, so
post-Z17.1 production triggers found `backlog=0` and the Notion writer

never got Notion pages at all.

The pilot demo runs on the Lead Feed. Bare shells aren't worth showing.

## Changes

### 1. `lib/orchestrator/orchestrator.ts` — Notion-staleness detection

`backfillNeedsWork()` now returns true when the row is otherwise enriched
but `isReadyForNotion(p) && notionNeedsSync(p)`. `notionNeedsSync(p)` is:

- `true` if `external_refs.notion_page_url` is missing (no page exists)
- `true` if `notion_written_at` is missing (older write path)
- `true` if `notion_written_at` < latest of `pitch_metadata.generated_at`
  and `gc_metadata.fetched_at` (page is stale relative to DB enrichment)
- `false` otherwise (Notion is in sync)

Both Notion pitch-update call sites (Wave 4 this-run + Wave 5 backlog)
also broadened: previously they only fired when `pitch_hooks.length > 0`,
so pre-window rows (which carry a deterministic tracking action but no
hooks by design) never had their Recommended Action column populated.
Now the call fires when EITHER hooks OR a non-empty `recommended_action`
is present. `pitchToNotionProperties` already handles empty hooks
gracefully (writes empty rich-text to Pitch Hook 1/2/3 slots).

### 2. `lib/adapters/zedcor/agency-contact-fallback.ts` (new) — free contact data

Hardcoded `Record<sourceSlug, AgencyContact>` for the 15 Texas / Houston-
area procurement sources we poll. Every entry is **department-level only**
(no individual names) and copied from each agency's **public** procurement
web page (the `source_url` field on each entry preserves the citation).
Examples:

- `harris-county-bonfire` → Harris County Purchasing Agent Office,
  `purchasingweb@hctx.net`, `(713) 274-4400`
- `houston-obo` → City of Houston OBO Help Desk, `obo@houstontx.gov`,
  `(832) 393-0600`
- `txdot-houston-district` → TxDOT Houston District Procurement,
  `(713) 802-5000`

News-source slugs (houston-business-journal, builders-exchange-texas,
news-engineering-record) are intentionally absent — those rows mention
the GC by name in the article body, so the right fallback is a
`news-gc-extractor` improvement under a separate sprint.

### 3. `buildPreWindowTrackingAction` accepts source slug

The pre-window tracking action now embeds `agencyContactSnippet(source)`
so the Recommended Action text carries a callable procurement contact
even when no GC is selected. Example after Z17.2 for ZED-58:

> Watch list. Owner bids are open through 2026-06-22. **Contact: Harris
> County Purchasing · (713) 274-4400 · purchasingweb@hctx.net.**
> Identify the GC the moment the contract is awarded — then re-pitch
> as a sub-bid. Reference: "ITB - Replacement of the Existing Generator
> at the Harris County Sheriff's Pr…". Touch base by 2026-06-22.

The rep now has someone to call about *every* pre-window construction
lead, not just the awarded ones.
